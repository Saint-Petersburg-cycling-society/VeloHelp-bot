# ПДн РФ — инженерный checklist

**Не юридическое заключение.** Этот файл фиксирует требования, которые влияют
на архитектуру и которые нужно подтвердить с юристом перед публичным запуском.

Проверено по состоянию на 2026-10-03.

## Почему считаем ПДн частью threat model

152-ФЗ определяет оператора широко: им может быть в том числе физическое лицо,
если оно организует/осуществляет обработку и определяет цели, состав данных и
операции над ними.

Telegram ID + связь с заявками/районами/точной геопозицией нельзя проектировать
исходя из предположения «это точно не персональные данные».

## До запуска проверить

- [ ] Кто является оператором ПДн.
- [ ] Нужно ли и как подать уведомление Роскомнадзору до начала обработки.
- [ ] Политика обработки ПДн опубликована и соответствует фактической системе.
- [ ] Основание обработки для каждого поля/операции.
- [ ] Если используется согласие — отдельный, доказуемый flow и версия текста.
- [ ] Сроки/условия прекращения обработки по каждой категории.
- [ ] Процедура запроса доступа/удаления/отзыва.
- [ ] Лицо/процесс, отвечающий за обработку обращений.
- [ ] Договоры/поручения с инфраструктурными подрядчиками, если нужны.
- [ ] Порядок инцидентов и утечек.
- [ ] Резервные копии подчиняются тем же retention/локализационным ограничениям.

## Локализация

С 1 июля 2025 ч. 5 ст. 18 152-ФЗ в общем случае запрещает при интернет-сборе
граждан РФ запись, систематизацию, накопление, хранение, уточнение и извлечение
их ПДн с использованием баз данных за пределами РФ, кроме указанных законом
исключений.

Следствие для архитектуры: production primary DB для пользовательских данных
нельзя по умолчанию ставить на текущий зарубежный VPS и «разобраться потом».

## Минимизация

Планируем хранить:
- Telegram user ID;
- consent metadata;
- helper settings;
- coarse areas;
- request lifecycle;
- exact point активной заявки;
- минимальный технический audit.

Не собираем без отдельной цели:
- email;
- телефон;
- домашний адрес;
- дату рождения;
- документы;
- историю перемещений.

## EN summary

This is an engineering checklist, not legal advice. Before public launch,
identify the personal-data operator, verify Roskomnadzor notification duties,
legal bases/consent flows, retention/deletion, incident procedures,
contractors, backups and the physical location of primary/backup storage.
Russian localization requirements must be re-checked against the actual
deployment immediately before launch.
